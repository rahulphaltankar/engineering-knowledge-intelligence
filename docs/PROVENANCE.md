# Provenance, classification, confidence and review

The demonstrator exposes an **evidence and reasoning trace** — the *auditable derivation* of
each finding. It is built from recorded evidence, traversal paths, deterministic scoring and
gate outcomes. It is not a transcript of model reasoning, and no model reasoning is shown.

## Provenance on every record

Every entity carries a mandatory `Provenance` stamped by the connector base class:

| Field | Fire-engineering example |
|---|---|
| `connector_id` | `FIRE_SIMULATION` |
| `source_system` | `Simulation / Public Data Connector` |
| `source_object_id` | `FTR-001` |
| `source_version` | `test_results.json` |
| `source_url` | `packs/fire-engineering/data (synthetic; generated by scripts/generate_fire_corpus.py)` |
| `licence` | `Synthetic demonstrator data - see docs/THIRD_PARTY.md` |
| `data_classification` | `SIMULATED — PUBLIC DEMONSTRATOR DATA` |
| `retrieved_at` | UTC timestamp of retrieval |

Every dataset file carries the same envelope:

```json
{
  "data_classification": "SIMULATED — PUBLIC DEMONSTRATOR DATA",
  "generated_by": "Engineering Knowledge Intelligence demonstrator",
  "seed": 42,
  "records": [ ... ]
}
```

Generated outputs carry the connector list, context snapshot id, record count, data
classification and model description.

## Classification

| Class | Meaning | Confidence |
|---|---|---|
| FACT | Retrieved directly from a source record | scored |
| DERIVED | Computed deterministically from records (traversal, set operations) | scored |
| INFERRED | Reasoned by a model from evidence (only when a model is configured) | scored, lower |
| ASSUMED | Stated without verifiable evidence; the assumption is declared | penalised |
| UNKNOWN | Not established by the available evidence; nothing assumed in its place | none (0.0) |

A synthesised finding is never classified more strongly than its weakest input.

## Confidence

Deterministic (`core/provenance.py::score_confidence`): evidence count, independent sources,
agreeing specialists, classification, inferred edges and derivation depth. The same inputs
always give the same score. It is **not** model self-reported confidence. The explain panel
states the inputs behind each score.

## Derivation path

Each finding carries:

- `rationale` — the rule of derivation in plain language (for example "FTR-001 records basis
  'office'; FEC-001 supersedes that basis. A pass obtained on a superseded basis does not count
  as coverage.")
- per evidence item, the **relationship path** by which traversal reached it
  (`FEC-001 ->AFFECTS-> FREQ-002`, `FREQ-002 ->VERIFIED_BY-> FTST-001`, …)
- the pipeline stages it passed through, with what each recorded
- `assumptions` and `unknowns`

## Evidence gate

Before any finding is shown:

- every cited id must exist in the retrieved context; fabricated ids are counted and reported
- ids mentioned only in prose are checked as well
- a model finding with no verifiable evidence is **removed**
- any other claim with no verifiable evidence is **downgraded to ASSUMED** with the
  assumption stated
- UNKNOWN findings pass through with only verified evidence attached

## Output validation

| Rule | Blocks delivery |
|---|---|
| `no_fabricated_ids` | yes |
| `no_invented_acceptance_criteria` — an unestablished row must carry `NOT ESTABLISHED` (fire) or `REQUIRES PROGRAMME SPECIFICATION` (automotive) | yes |
| `human_review_applied` — no rejected finding presented in a finding list | yes |
| `required_sections_present`, `unknowns_declared`, `all_claims_cited` | reported |

## Evidence transferability

When the subject record declares `baseline_basis` and `proposed_basis`, the context records
the superseded basis. A result or evidence record whose `basis` is superseded is not
transferable; a pass on it is reported as `evidence_not_transferable`, with the reason
"Obtained on the 'office' basis; the change under analysis establishes the 'residential'
basis, so this evidence does not transfer." An explicit `transferable: false` on a record is
also honoured, and the automotive dataset's free-text markers still apply.

## Human review record

Stored beside the finding, never inside it:

```json
{
  "finding_id": "TRF-0010",
  "decision": "rejected",
  "reviewer": "Demo Reviewer",
  "note": "…",
  "timestamp": "2026-09-14T00:55:09+00:00",
  "finding_snapshot": {
    "statement": "…",
    "classification": "DERIVED",
    "confidence_score": 0.76,
    "evidence_ids": ["FTR-001", "FTST-001", "FREQ-001", "FREQ-002", "FEV-001", "FEC-001"]
  },
  "run_id": "…",
  "context_snapshot_id": "…",
  "control": "Demonstrator review control — session scoped, unauthenticated"
}
```

The snapshot preserves what the reviewer actually saw. **This control is session scoped and
unauthenticated**: the reviewer name is self-declared, records disappear with the session,
and nothing here constitutes identity, approval, competence verification or sign-off.
